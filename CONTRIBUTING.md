# Contributing to SPLENDID

Thank you for your interest in helping build SPLENDID.

## Before contributing

- Read the project overview and current roadmap.
- Check whether an issue or proposal already exists.
- Keep contributions focused and explain the problem being solved.
- Do not include private keys, seed phrases, passwords, personal data, or confidential information.

## Changes

For a proposed change, include:
- what changed;
- why it is needed;
- how it was tested;
- any limitations or security implications;
- whether documentation needs updating.

Do not describe a feature as complete unless the implementation and relevant verification are included.

## Token and financial claims

Contributors must not publish unsupported claims about token price, returns, liquidity, exchange listings, partnerships, audits, rewards, or legal approval. Proposed features must be labelled as proposals.

## Responsible disclosure

Do not publish exploitable vulnerability details in public issues. Follow the reporting guidance in [Security Policy](docs/SECURITY.md).

## Project conduct

Be respectful, constructive, and transparent. Harassment, scams, impersonation, and requests for wallet recovery phrases or private keys are not acceptable.

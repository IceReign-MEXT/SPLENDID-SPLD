# SPLENDID Development Roadmap

**Roadmap status:** Initial targets; dates and features may change after testing.

## Phase 0 — Foundation

- [x] Create public GitHub repository.
- [x] Record project identity and provisional token parameters.
- [x] Establish Devnet-first and free-first principles.
- [ ] Confirm brand assets and usage rights.
- [ ] Check name and ticker conflicts.
- [ ] Publish a project FAQ and risk disclosures.

## Phase 1 — Solana Devnet prototype

- [ ] Choose and document token decimals.
- [ ] Set up a dedicated Devnet test wallet.
- [ ] Create a test mint using a documented, reproducible process.
- [ ] Add and verify token metadata.
- [ ] Mint only the planned test supply on Devnet.
- [ ] Transfer test tokens between two test wallets.
- [ ] Record the mint address and explorer links.
- [ ] Verify supply and authority settings independently.

Devnet assets have no intended monetary value. Never ask community members to pay for test tokens.

## Phase 2 — SPLENDID information website

- [ ] Publish the project purpose, current status, and roadmap.
- [ ] Explain SPLD's proposed purpose and limitations.
- [ ] Publish token design and risk documentation.
- [ ] Add links to official project channels only after they are verified.
- [ ] Make the site mobile-friendly and accessible.

## Phase 3 — SPLENDID Hub prototype

- [ ] Add read-only token information.
- [ ] Add optional wallet connection.
- [ ] Display the connected wallet's Devnet SPLD balance.
- [ ] Link transactions to a Solana explorer.
- [ ] Clearly label all Devnet data as test data.
- [ ] Add community polls that are initially off-chain and non-binding.

## Phase 4 — Useful products and community

- [ ] Interview potential users about real problems.
- [ ] Select one small, useful digital service to build.
- [ ] Test it with users and publish what was learned.
- [ ] Explore paid software services or digital products.
- [ ] Keep commercial revenue separate from token-price speculation.

## Phase 5 — Security, legal and launch assessment

- [ ] Review application and wallet security.
- [ ] Review authority and treasury controls.
- [ ] Obtain qualified legal advice on relevant jurisdictions.
- [ ] Complete disclosures and independent review appropriate to the product.
- [ ] Estimate launch and ongoing operating costs.
- [ ] Make and publish a documented go/no-go decision.

## What is not on this roadmap yet

No mainnet launch date, token sale, liquidity pool, exchange listing, staking yield, token-holder profit share, or guaranteed reward is approved. Such items must not be implied by marketing materials.
